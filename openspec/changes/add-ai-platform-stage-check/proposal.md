# 变更：个人 AI 应用平台阶段性验收

## 为什么做

个人项目需要在第 3～6 课成果上完成一次累计验收。系统必须把多个 AI 应用、提示词模板、班级知识库、内置与上传 Skill、外部工具和 MCP 接入到同一条真实对话链路，并用可查看的运行轨迹回答教师指定的五个验证问题。

## 交付内容

- 每班可配置并选择多个 AI 应用；每个应用绑定提示词模板、材料和 Skill。
- 教师可维护提示词模板，模板变量在服务端渲染后进入 LLM 系统消息。
- 使用课程向量接口生成知识切片向量并写入内部 Qdrant；对话只在应用绑定的本班材料中执行关键字与向量 RRF 混合检索，并只把 Top-K 命中切片传给 LLM。
- 系统预置 Skill；教师可以上传课程规定格式的 Skill 文本文件。
- 服务端在应用绑定且启用的 Skill 中确定性选择至多一个，并把被选 Skill 的完整说明正文注入系统消息。
- 自建 MCP Server 与主应用由 Docker Compose 一并启动；宿主完成登记、握手、工具发现、最小候选集、模型决策、参数校验、工具执行、结果回传及调用记录。
- 对话使用 SSE 返回 `meta`、`tool`、`delta`、`done` 或 `error` 事件。
- 保存脱敏的 LLM 请求、LLM 返回、检索切片、Skill 选择过程和 MCP 调用轨迹，供教师在页面中逐项核验。

## 影响范围

- Go API：新增 AI 应用、模板、Skill、会话、向量检索、LLM、MCP 与验收轨迹接口。
- MySQL：新增相关业务表、可追溯知识切片和班级隔离关系。
- Qdrant：保存 2048 维向量与最小关联 payload，不保存正文。
- React：新增 AI 对话、应用配置、Skill、MCP 和调用验证页面。
- Docker Compose：新增自建 MCP 工具服务并补充模型配置。
- 文档与测试：更新 README，增加自动化测试和阶段验收 Markdown 报告。

## 不在本次范围

- 不训练或微调基础模型。
- 不把 API Key、MCP Token 或完整认证信息返回给浏览器。
- 不将整个知识库或所有 Skill 无差别发送给 LLM。
- 不允许模型直接访问数据库或自行绕过宿主调用工具。
