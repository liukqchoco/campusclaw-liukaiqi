## Why

CampusClaw 面向中小学教研场景。当前教学材料散落在群文件和网盘中，教师难以统一管理，学生也缺少稳定的本班资料入口。首个迭代先建立身份、角色与班级边界，再完成材料上传和知识库入库，为后续检索能力提供可信的数据底座。

## What Changes

- 教师和学生通过账号密码登录；未登录用户不能读取受保护数据。
- 教师可以上传、查看和下载本班材料；学生只能查看和下载。
- 所有材料查询在服务端按当前会话所属班级过滤；跨班详情和文件访问返回 404。
- 教师上传 `.txt` 或 `.md` 后，系统保存原文件、解析 UTF-8 正文，并在同一事务中写入材料表和知识库表。
- 提供双班级、教师与学生预置账号及可区分的样本材料。
- 通过 Nginx、Go、MySQL 和 Docker Compose 提供可复现的单实例部署。
- 提供公开的 `GET /health` 存活接口，业务接口统一位于同源 `/api` 路径。
- README 说明启动方法、预置账号、范围、非目标、单实例限制及跨班返回码。

## Capabilities

### New Capabilities

- `auth-upload`: 账号登录、服务端会话、角色授权、班级隔离、材料上传与知识库入库、鉴权查看和下载。

## Impact

- 新增 React 前端、Go API、MySQL 数据库和 Nginx 入口。
- 新增 `Dockerfile`、`docker-compose.yml`、`.env.example`、数据库初始化和种子数据。
- 新增本地持久化卷：MySQL 数据和 API 上传目录。
- 浏览器只访问 Nginx；API 与数据库不直接映射到宿主端口。

## Non-goals

- 不实现向量检索、RAG、智能问答或聊天助手。
- 不实现作业提交、批改、成绩、错题本。
- 不实现注册、找回密码、短信或邮箱验证码。
- 不实现 OAuth、OIDC、SSO 或多学校租户。
- 不实现管理员角色、跨班管理或审计后台。
- 不实现 Kubernetes、多副本高可用或完整 CI/CD。
- 不以隐藏按钮或前端角色字段作为访问控制。
